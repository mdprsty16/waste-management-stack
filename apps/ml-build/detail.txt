DOCUMENTATION: API CONTRACT & RECURSIVE WORKFLOW FOR THRESHOLD (BSSB)
======================================================================

Deskripsi Alur Baru:
Backend mengirimkan data transaksi historis (masa lalu) hingga hari ini, 
beserta batas kapasitas maksimal (threshold) dan volume sampah saat ini. 
Engine Python (.py) akan melakukan simulasi peramalan maju berulang kali 
(Recursive Forecasting) hari demi hari di dalam memori untuk mendeteksi 
tepat pada hari ke berapa penampungan sampah akan penuh (mencapai threshold).

----------------------------------------------------------------------
1. SPESIFIKASI ENDPOINT (API CONTRACT)
----------------------------------------------------------------------
Method       : POST
Path         : /api/v1/predict/threshold-dss
Content-Type : application/json

Ketentuan Pengiriman Data dari Backend:
- Backend mengirimkan data transaksi historis minimal 10-14 hari ke belakang 
  (urut terlama ke terbaru) untuk membentuk landasan fitur lag harian.
- Tidak perlu mengirimkan baris dummy untuk hari esok, karena hari esok dan 
  seterusnya akan digenerate otomatis secara rekursif oleh Python.
- Backend wajib menyertakan nilai 'threshold_m3' dan 'current_fill_m3'.

4. ALUR PIPELINE RECURSIVE DI DALAM FILE PYTHON (.py)
----------------------------------------------------------------------
Ketika API menerima request, script Python akan menjalankan algoritma ini:

TAHAP A: ADOPSI LOGIKA PREPROCESS & AGREGASI AWAL
1. Membaca 'threshold_m3' dan 'current_fill_m3' ke dalam variabel memory.
2. Mengubah 'raw_transactions' menjadi Pandas DataFrame historis.
3. Menghitung volume riil (berat / densitas), menghapus outlier (>10 m³).
4. Melakukan agregasi harian dan penggabungan transaksi hari Minggu ke Senin.
5. Membuat kolom dasar awal: 'is_monday' dan 'log_volume_m3'.

TAHAP B: INISIALISASI LOOP FORECASTING REKURSIF
6. Mencatat tanggal terakhir dari data historis (anggap sebagai Hari T).
7. Membuat variabel tracker penampungan: `total_accum_m3 = current_fill_m3`.
8. Membuat loop `while total_accum_m3 < threshold_m3` (maksimal limit 30 hari):

   Di dalam Loop Jalankan Langkah ini setiap Hari Baru (T + i):
   a. Buat baris baru dengan Tanggal maju 1 hari (T + 1, T + 2, dst).
   b. Ekstraksi Fitur Kalender Otomatis pada tanggal baru tersebut:
      - nama_hari = tanggal_baru.dt.day_name()
      - is_monday = 1 jika Senin, else 0
      - is_saturday = 1 jika Sabtu, else 0
      - is_low_traffic = 1 jika Rabu atau Jumat, else 0
   c. Hitung Fitur Lags & EWM secara dinamis dari data gabungan:
      - 'lag_6d' & 'lag_9d' (mengambil nilai volume asli beberapa baris ke belakang).
      - 'ewm_3d' (menghitung rata-rata eksponensial bergerak 3 hari terakhir).
   d. Isolasi baris baru tersebut menjadi vektor fitur X:
      👉 ["is_monday", "is_saturday", "is_low_traffic", "lag_6d", "lag_9d", "ewm_3d"]
   e. Prediksi Volume menggunakan model Ridge:
      - model.predict(X) -> menghasilkan nilai skala LOG.
      - Inversi balik: prediksi_m3 = np.expm1(nilai_log)
   f. Update Dataframe & Akumulasi:
      - Isi kolom 'volume_m3' dan 'log_volume_m3' pada baris baru tersebut dengan 
        hasil prediksi barusan (sehingga hari esoknya bisa membaca baris ini sebagai lag).
      - Tambahkan hasil prediksi ke variabel penampung: 
        `total_accum_m3 += prediksi_m3`
   g. Catat langkah simulasi ke dalam array hasil.
   h. Jika `total_accum_m3 >= threshold_m3`, loop BERHENTI.

TAHAP C: PENYUSUNAN REKOMENDASI DSS
9. Menghitung selisih hari dari Hari T sampai loop berhenti (`days_until_threshold`).
10. Membuat teks string rekomendasi dinamis berdasarkan jumlah hari tersebut.
11. Mengirimkan seluruh payload JSON Response kembali ke backend/Next.js.
